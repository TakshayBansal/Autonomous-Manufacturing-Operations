# Connected factory demo: end-to-end validation

## What is in the workbook

`GenuineGigs_Connected_Automotive_Factory_v2.xlsx` contains operational facts,
not expected answers:

- 20 material/product SKUs: 8 finished products, 4 shared subassemblies, and 8 purchased components;
- 12 multi-level BOMs with components reused across several OEM products;
- 8 customer commitments for Honda, Tata Motors, and Mahindra;
- 8 production work orders on 4 assembly lines;
- 4 approved suppliers, 8 purchase orders, supplier/material qualifications, and dated schedules;
- current inventory, safety stock, MOQ/order multiples, and deliberately varied supplier delays.

The workbook contains no cases, recommendations, scores, decisions, or recovery
results. Those records must be generated by the application after import.

## Run the demo

1. Start the stack and sign in as a workspace administrator.
2. Create or select a **Demo** workspace. Use a new workspace for a clean run;
   loading a fixture never deletes customer or previously imported data.
3. Open **Administration** and choose **Load 20-SKU connected factory**.
4. Open the reported highest-exposure case, then inspect **Command Center**,
   **Cases**, **SCM → Exceptions**, **SCM → Supply Horizon**, Procurement, and
   Operations. The same component codes, OEM products, suppliers, orders, and
   work orders should appear across those surfaces.
5. Open an at-risk material. Confirm that its inventory trajectory, dated
   demand, supply, affected BOM parents, pegs, and recommendation are visible.
6. Check the recommendation reason, dates, quantity, constraint results, score
   dimensions, and evidence. The case decision alternative links back to the
   SCM recommendation and immutable planning snapshot.
7. Click **Accept**, then **Confirm demo execution**. This control is available
   only in demo/simulation workspaces outside production. It changes the
   simulated source schedule, records an audit event, and immediately replans.
8. Confirm the shortage disappears from the latest projection. The case must
   remain in monitoring after this first successful cycle; action completion is
   not recovery proof.
9. Return to **SCM** and click **Run planning** for the next normal worker-backed
   cycle. For a synchronous API check, use `POST /scm/planning-runs/run-now`
   with the browser session's CSRF token. After two distinct fresh covered
   cycles, the case recovery state becomes `RECOVERED`.
10. Ask Gigi: “What are the highest-impact material cases?”, “Why is this
    component at risk?”, “Which products and customers depend on it?”, and
    “Did we solve it?”. Verify that quantities match case/planning evidence and
    that Gigi describes monitoring versus verified recovery correctly.

## Negative checks

- Reject or defer an option and verify that source schedules do not change.
- Try confirming an option before accepting it; the API must return `409`.
- Try confirming an option whose deterministic simulation does not resolve the
  risk; the API must return `409`.
- Change an inventory observation to be stale and replan; the risk becomes
  unknown and cannot be treated as a high-confidence recommendation.
- Replay the same workbook; ingestion receipts prevent duplicate source facts.
- Attempt the simulated-execution endpoint in a production/customer workspace;
  it must be unavailable.

## Automated proof

From `apps/api` run:

```bash
.venv/bin/pytest -q tests/test_unified_factory_import.py
```

The connected-factory test asserts the 20-SKU/12-BOM import, multiple calculated
risks, shared cases, ranked decision alternatives, recovery targets, a resolving
simulation, source application, replanning, and two-cycle recovery verification.
